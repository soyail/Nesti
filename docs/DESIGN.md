# 交互与视觉原则

## 设计目标

栖伴应当感觉像一个有性格的桌边伙伴，而不是浮在桌面上的通知中心。界面要允许用户一眼理解、一秒忽略、随时反悔。

## 体验原则

### 安静是一种完整状态

宠物可以用呼吸、眨眼、轻微视线移动表达存在，不需要始终显示气泡或索取回应。

### 主动互动必须轻量

主动气泡默认一到两句，支持直接忽略。常见操作不超过三个，如“知道了”、“稍后提醒”、“关闭这类提醒”。

### 不使用监控语言

避免精确描述键鼠活动、不活跃时长或应用使用细节。优先使用“专注一阵子了”等模糊但足够的表达。

### 情绪不取代可用性

动画和文案可以有性格，但必须有明确的操作结果。不得用“宠物会难过”等设计阻止用户关闭提醒或删除数据。

## 主要交互容器

- **宠物本体**：存在感、拖拽和快速入口。
- **短气泡**：问候、鼓励和低优先级提醒。
- **对话卡片**：用户主动聊天、日记和工作回顾。
- **设置面板**：提醒偏好、勿扰、权限、数据和模型设置。
- **托盘/菜单栏**：显示/隐藏、暂停感知、暂停提醒和退出。

## 文案准则

- 体贴、简短、自然、有上下文、可忽略。
- 提建议而不下命令，不使用恐惧和愧疚感。
- 用户情绪低落时先承接情绪，再询问是否需要建议。
- 不把推测表述为事实；不伪装记得未保存的内容。

## 可访问性底线

- 关键操作支持键盘，焦点状态清晰。
- 不仅依赖颜色传达情绪或状态。
- 支持减少动效，并避免快速闪烁。
- 气泡字号、对比度和点击区域满足平台可访问性指南。
