# 可靠性

## 可靠性目标

栖伴的首要可靠性目标不是“每次都要说话”，而是在不确定或失败时保持安静、不重复打扰、不丢失用户控制。

## 故障域与降级

| 故障 | 预期降级 |
| --- | --- |
| LLM 超时或不可用 | 保留宠物与本地功能，显示简短可重试状态 |
| 本地存储不可写 | 不伪装保存成功，暂停依赖持久化的功能 |
| 感知权限被拒绝 | 使用时间和用户明示状态，降低主动频率 |
| 调度器重复触发 | 通过幂等键和冷却记录抑制重复提醒 |
| 应用异常退出 | 恢复安全窗口位置，不自动重放过期主动消息 |
| 休眠/唤醒事件重复 | 去抖并刷新当前能力，丢弃过期候选 |
| 多显示器或 DPI 变化 | 将宠物修正到当前可见且可拖拽区域 |
| 更新安装失败 | 保留当前可运行版本和原数据，提供重试/手动恢复 |
| 连续启动崩溃 | 进入安全模式，禁用非必要适配器与动画 |

## 主动行为保障

- 对每个已展示行为保存幂等标识、类型、时间和结果。
- 决策快照应使用同一时钟源，以便确定性测试冷却和静默时段。
- 应用重启、时区变化和夏令时切换不得造成提醒风暴。
- 过期的候选行为直接丢弃，不在用户恢复活跃后集中展示。
- 唤醒、重连、升级和迁移完成后使用保守冷却，不立即产生与恢复无关的主动互动。

## 可观测性

记录结构化事件，如 `care_evaluated`、`care_suppressed`、`llm_failed`、`storage_failed`，但不记录完整对话或桌面内容。对主动行为应能解释“为什么展示/为什么保持安静”。

## 测试策略

- 单元测试：冷却、拒绝退避、连续忽略、静默时段和优先级冲突。
- 集成测试：调度触发到持久化结果的完整流程。
- 故障注入：LLM 超时、存储失败、权限拒绝、时钟跳变和进程重启。
- 端到端测试：关闭、延后、标记完成和暂停提醒。
- 平台契约测试：macOS/Windows 适配器对不支持、权限拒绝和临时不可用返回一致语义。
- 发布测试：签名安装、覆盖升级、中断回滚、卸载和数据保留/删除。

## 待定义的服务目标

在技术栈和发布渠道确定后，补充启动成功率、崩溃率、本地写入可用性、LLM 延迟分位数、重复提醒率、空闲 CPU 和稳态内存的可量化目标。测试组合由 [TEST_MATRIX.md](TEST_MATRIX.md) 维护。
