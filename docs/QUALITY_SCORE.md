# 质量评分

本表用于设计评审、里程碑和发布前检查。每项按 0–2 分评估：`0` 未满足，`1` 部分满足，`2` 有证据满足。

| 维度 | 检查问题 |
| --- | --- |
| 产品价值 | 功能是否提供低干扰、有温度的实际价值？ |
| 用户控制 | 是否可关闭、延后、撤回或删除？ |
| 隐私 | 数据和权限是否最小化、可解释？ |
| 架构 | 业务逻辑是否与 UI、定时器和外部 SDK 分离？ |
| 可测试性 | 关键决策是否可用可控时钟和假适配器测试？ |
| 可靠性 | 失败时是否安静降级，不丢数据、不重复打扰？ |
| 平台兼容 | 承诺的 macOS/Windows 版本、架构和窗口能力是否有真实环境证据？ |
| 发布安全 | 安装、签名、更新校验、中断恢复和卸载是否通过验证？ |
| 可访问性 | 键盘、对比度、减少动效和语义是否达标？ |
| 文档 | 规格、决策、迁移和运维信息是否同步？ |

## 评分解读

- **18–20**：可进入发布候选，前提是没有安全或隐私阻断项。
- **13–17**：可合并到非发布分支，需有明确后续计划。
- **0–12**：不应发布，先解决主要缺口。

任何隐私、数据删除、密钥泄露或高频打扰问题都是独立阻断项，不能用总分抵消。
