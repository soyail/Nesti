# 桌面技术选型

## 状态

Proposed。该建议需要用透明窗口、点击穿透、托盘、多显示器和签名打包原型验证后才能转为 Accepted。

## 需求

### 功能需求

- macOS 和 Windows 上的透明置顶桌面宠物。
- 平滑但可降级的动画、气泡、对话卡片和设置界面。
- 托盘/菜单栏、全局快捷键、通知、开机启动和本地安全存储。
- 平台无关的 Agent、记忆和主动关怀业务逻辑。

### 非功能需求

- 长期驻留时的 CPU、内存和电量成本可控。
- UI 不被 LLM、存储或系统感知阻塞。
- 平台 API 可模拟、可契约测试、可替换。
- 支持签名、公证、安装、升级和故障回滚。

## 备选方案

| 方案 | 优势 | 主要代价 |
| --- | --- | --- |
| Flutter Desktop | 统一 UI，动画表现好，领域逻辑可使用纯 Dart | 桌面宠物窗口能力仍需插件或原生代码 |
| Tauri | 安装包和运行时成本较低，Rust 安全边界清晰 | Web/Rust 双技术栈，特殊窗口能力仍需平台适配 |
| Electron | 桌面生态成熟，Web 团队上手快 | 长期驻留的内存、产物体积和运行时成本较高 |
| 完全原生 | 系统集成和细节控制最强 | 两套 UI 与更高长期维护成本 |

## 建议

优先使用 Flutter Desktop 进行技术原型，但将选型视为可证伪假设：

- 主动关怀、记忆、隐私决策和 Orchestrator 使用纯 Dart，不依赖 Widget 或具体插件。
- 系统能力通过显式接口访问，macOS 和 Windows 分别提供适配器。
- 只有当原型在两个平台通过窗口、性能和发布检查后，才将 [ADR-0001](../adr/0001-desktop-technology-stack.md) 改为 Accepted。

## 原型验收

1. 宠物窗口可透明、置顶、拖拽，且非交互区域不阻挡鼠标。
2. 在两端多显示器与不同缩放下位置正确。
3. 隐藏/安静时动画和轮询显著降频。
4. 托盘/菜单栏、单实例、休眠唤醒和退出流程可用。
5. 已签名 macOS 和 Windows 测试产物可在干净机器启动。

## 风险

- 第三方插件的平台能力、维护状态和签名兼容性可能不足。
- 将所有桌面能力放入一个大型插件会形成新的紧耦合。
- 如过早承诺 Intel、Windows 10 或 ARM64，测试与发布成本会迅速扩大。
