# 桌面应用生命周期

## 状态

Proposed。

## 目标

让 Nesti 在安装、启动、驻留、休眠、唤醒、更新和卸载过程中保持可预测，不补发过期提醒，不丢失用户控制。

## 状态模型

```text
installed -> starting -> ready -> hidden/background
                    |       |          |
                    |       -> suspended -> resuming
                    |                    |
                    -> degraded <--------
                                |
                         updating -> restarting
                                |
                            shuttingDown
```

`degraded` 是可运行状态，表示部分能力因权限、网络、存储或平台限制不可用。

## 启动流程

1. 确保单实例；第二实例将焦点交给已运行实例后退出。
2. 读取最小启动配置，检查 schema 版本与必要迁移。
3. 恢复窗口位置，并将不再可见的坐标修正到当前显示器。
4. 启动核心服务后再启用感知和调度；不因启动延迟补发过期事件。
5. 非关键适配器失败时进入 `degraded`，不阻止宠物、设置和退出。

## 休眠与唤醒

- 休眠前停止动画驱动、感知轮询、普通调度与非必要网络请求。
- 唤醒后重新读取当前时间、时区、显示器、网络和权限状态。
- 唤醒前已过期的候选主动行为直接丢弃。
- 唤醒后设置一段保守冷却，避免系统事件集中导致多次评估。

## 时间与显示器变化

- 持久化时间使用绝对时间点，静默时段使用用户当前时区解释。
- 时区、夏令时或系统时钟跳变后重新计算候选，不重放历史。
- 显示器移除、主屏切换或 DPI 变化后，宠物保持在可见且可拖拽区域。

## 关闭、退出与崩溃

- 关闭对话/设置窗口不等于完全退出，托盘/菜单栏必须提供“退出 Nesti”。
- 正常退出时先停止调度和新请求，再完成必要的原子写入与资源释放。
- 崩溃恢复只恢复安全状态，不自动重放未确定是否已展示的提醒。
- 如连续启动崩溃，进入安全模式：禁用非必要适配器与动画，保留设置、数据导出和退出。

## 升级与迁移

- 安装更新前完成数据迁移可行性检查，不在无回滚方案时执行不可逆迁移。
- 迁移失败不伪装启动成功，保留原数据和恢复指引。
- 更新完成后不立即展示与更新无关的主动气泡。

## 卸载与数据

卸载程序与“删除所有数据”是两个不同操作。产品必须明确说明卸载是否保留数据，并在应用内提供可验证的完整删除流程。

## 故障模式

| 故障 | 预期处理 |
| --- | --- |
| 单实例锁异常 | 不启动两个调度器，向用户提供恢复/退出路径 |
| 存储不可写 | 进入降级，停止需要持久化的主动行为 |
| 窗口位置无效 | 回退到主显示器安全位置 |
| 唤醒事件重复 | 使用事件去抖和恢复世代号防重 |
| 迁移失败 | 保留原数据，不启动写入新 schema 的服务 |
