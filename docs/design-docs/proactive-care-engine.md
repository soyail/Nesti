# 主动关怀决策模型

状态：建议设计，待实现。

## 目标

将主动提醒建模为可测试的决策过程，而不是分散在 UI 和定时器中的固定弹窗。

## 候选行为

每个候选行为至少包含：

```text
type, reason, priority, createdAt, cooldown,
quietHours, userPreference, dismissible,
suggestedMessage, expectedAction
```

建议额外包含 `expiresAt`、`deduplicationKey`、`sourceSignals` 和 `policyVersion`，用于过期丢弃、防重和可解释性。

## 决策阶段

1. **生成**：根据类型、用户配置和时间生成候选行为。
2. **硬性抑制**：检查功能关闭、勿扰、静默时段、全屏/演示/会议和过期。
3. **频率控制**：检查同类冷却、跨类全局冷却、近期拒绝与连续忽略。
4. **上下文评估**：工作状态、用户近期主动互动和当前对话是否繁忙。
5. **排序与裁决**：同一时刻最多选择一个行为，或输出 `quiet`。
6. **记录结果**：保存展示、忽略、延后、完成或关闭类型等结果。

## 默认策略

- 喝水：用户可配置，默认不高于每 60–90 分钟一次。
- 活动：用户可配置，默认不高于每 90 分钟一次。
- 开工问候与结束回顾：每日各最多一次。
- 拒绝后：延长同类冷却，不在短时间内换话术重试。
- 连续忽略：逐步降低所有主动行为频率，直至安静状态。

## 测试要求

使用可注入时钟和表格驱动用例，覆盖时区、跨日、夏令时、重启、重复触发、拒绝、忽略、延后、勿扰和权限缺失。相同输入必须产生相同决策。
