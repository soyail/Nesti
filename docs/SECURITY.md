# 安全与隐私

## 信任承诺

栖伴处理桌面状态、对话和日常记录。任何“更智能”的改进都不能默认以收集更多敏感信息为代价。

## 数据分类

| 等级 | 示例 | 默认策略 |
| --- | --- | --- |
| 公开 | 应用版本、非用户化的功能配置 | 可记录必要运行信息 |
| 内部 | 提醒类型、匿名错误码 | 最小化保留 |
| 个人 | 偏好、提醒历史、粗粒度工作状态 | 本地优先，支持删除与导出 |
| 敏感 | 完整对话、日记、长期记忆、API Key | 加密/安全存储，禁止进入普通日志 |
| 默认禁止 | 密码、完整屏幕内容、键入内容、剪贴板、私人通信 | 不收集 |

## 权限原则

- 默认最小权限，在功能首次需要时再申请。
- 申请前用用户能理解的语言说明用途、收集范围和关闭后的影响。
- 拒绝权限不得阻断无关功能，且不反复强迫请求。
- 外部 Agent、IDE 和系统集成默认只读。

## LLM 数据边界

1. 调用前根据用户设置组装最小上下文。
2. 执行脱敏和禁用范围过滤，记录“发送了哪类数据”而非完整内容。
3. 不将 API Key、系统密钥或未授权桌面内容加入 prompt。
4. 允许按数据类型关闭上传，并对功能降级给出清晰说明。

## 本地存储

- 密钥使用 macOS Keychain 或 Windows DPAPI/Credential Manager 等操作系统安全存储，不写入代码、普通配置或日志。
- 安全存储不可用时，敏感功能停用，不以明文文件作为兼容性降级。
- 向用户展示数据目录、保留策略和删除范围。
- “删除所有数据”需要明确确认、执行结果和失败恢复说明。
- 备份和导出不得意外包含密钥或调试日志。

## 发布与供应链

- macOS 应用和嵌套二进制必须签名，官网发布产物必须通过 Notarization。
- Windows 应用和安装包必须使用 Authenticode 签名与可验证时间戳。
- 更新客户端必须验证元数据、产物签名、哈希、版本和分发渠道。
- 签名证书和私钥不进入仓库、常规 CI 日志或开发者本地配置模板。
- 发布前检查产物中的依赖、原生插件和更新组件，并生成可追溯的依赖/SBOM 记录。

## 日志底线

禁止记录 API Key、完整 prompt/对话、日记正文、屏幕内容和个人识别信息。错误日志使用事件 ID、匿名错误码和必要的布尔/枚举状态。

## 发布前安全检查

- 权限用途与实际调用一致。
- 所有敏感字段有存储、导出、删除和日志策略。
- 网络失败时不重试上传已被用户删除或撤回的内容。
- 依赖项和打包产物不包含开发密钥、本地数据或调试资料。
- 签名、公证、更新包篡改和降级攻击测试已通过。
