# 执行计划规则

## 何时需要计划

出现以下任一情况时，在 `exec-plans/active/` 创建计划：

- 涉及多个模块或预计跨多次工作会话。
- 改变架构、数据模型、权限、隐私或用户交互流程。
- 需要数据迁移、灰度发布、回滚或运维协调。
- 风险或不确定性需要在实施前被显式记录。

## 文件命名

`YYYY-MM-DD-<short-topic>.md`，例如 `2026-08-19-proactive-care-mvp.md`。

## 最小内容

1. 目标与非目标。
2. 现状与已知约束。
3. 方案和被放弃的备选方案。
4. 分阶段任务、验证方式和完成标准。
5. 风险、隐私影响、回滚方式和未解问题。
6. 进展日志和最终结果。

## 生命周期

1. 将已评审的计划放入 `active/`。
2. 执行中持续更新勾选项、偏差和新发现。
3. 完成后记录实际验证结果和剩余技术债。
4. 将文件移入 `completed/`，并在需要时更新索引与技术债跟踪。

## 模板

使用 [exec-plans/PLAN_TEMPLATE.md](exec-plans/PLAN_TEMPLATE.md)。
