# 构建与发布

## 文档状态

- 状态：Proposed
- 前置条件：桌面技术栈与分发渠道 ADR 被接受后补充具体命令

## 发布原则

- 所有对外构建必须可追溯到版本、提交和构建配置。
- 不在构建产物、日志、符号文件或更新元数据中包含开发密钥与用户数据。
- 安装、升级和卸载默认不需要管理员权限。
- 更新不得在用户专注、会议、演示或全屏时强制重启。

## macOS 发布流程

1. 在受控 macOS 构建环境生成对应架构的 Release 产物。
2. 审查 entitlements，只保留已由功能和权限文档解释的项目。
3. 启用 Hardened Runtime，使用 Developer ID 签名应用及所有嵌套二进制。
4. 提交 Apple Notarization 并将票据 staple 到最终产物。
5. 生成 DMG 或 PKG，在新用户机器上验证 Gatekeeper、首次启动和权限请求。
6. 如需同时支持 Intel 与 Apple Silicon，明确使用 Universal 构建还是分架构产物。

## Windows 发布流程

1. 在受控 Windows 构建环境生成 x64 Release 产物。
2. 生成 EXE/MSIX 安装包，审查安装路径、启动项、升级码和卸载行为。
3. 使用可信代码签名证书对应用和安装包进行 Authenticode 签名与时间戳。
4. 在干净设备上验证 SmartScreen、安装、覆盖升级、降级拦截和卸载。
5. 如技术栈依赖 WebView2 或其他运行时，明确最低版本、检测和安装策略。

## 自动更新安全

- 更新元数据和二进制必须通过 HTTPS 获取并验证签名。
- 未通过签名、哈希、版本或渠道检查的更新不得安装。
- 下载、校验、安装和重启为独立阶段，失败后保留当前可运行版本。
- 更新服务不复用 LLM API Key，也不获取对话、记忆或桌面上下文。
- 支持稳定渠道；如未建立回滚和遥测能力，不提供自动预览渠道。

## 发布检查清单

- [ ] 版本号、更新说明与数据迁移版本一致。
- [ ] macOS 签名、Notarization 和 Gatekeeper 验证通过。
- [ ] Windows 应用与安装包签名验证通过。
- [ ] 干净安装、上一版升级、中断恢复与卸载验证通过。
- [ ] 安装包不包含密钥、本地数据、未脱敏日志或调试服务。
- [ ] [TEST_MATRIX.md](TEST_MATRIX.md) 中的发布阻断用例已完成。
